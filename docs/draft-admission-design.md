# 草稿、输入历史与接纳

## 一份输入，一套历史

`Draft` 管理完整输入：文字、光标、附件以及剪贴板读取。`Editor` 只管文字编辑和布局；它不再单独保存纯文本历史。

宿主接收入队后，将输入快照追加到统一历史。↑/↓ 或 Ctrl-P/N 浏览这份历史，成功、失败、明确拒绝不另设恢复机制。拒绝事件只显示原因，不替换当前草稿，不追加重复历史。

历史保存最近 100 条，随 Draft 在当前 TUI 进程内跨会话保留。启动时用已保存会话的文本初始化；本次运行的历史保存完整附件，原始文件引用不新增持久化格式。

## 所有权与生命周期

- 当前输入拥有编辑器、附件和读图任务。历史快照只复制文字和附件，不复制后台任务。
- 浏览历史时，把未发送的当前输入整体暂存；返回最新位置时整体取回，光标和未完成读取也随之恢复。发送历史中的输入后继续保留原草稿。
- 文件补全只消费选择和导航事件，普通编辑与粘贴走同一路径；编辑后集中清除失去标记的附件，展示与提交直接读同一份有效列表。
- 清空附件取消当前输入的读图；丢弃输入由其 Drop 取消任务。历史中保存的草稿不会把迟到图片写到正在浏览的其他输入。
- Draft 属于进程内的界面状态；切换会话只替换 SessionView，不搬移或重建草稿。cwd 变化会废弃旧扫描结果；已选绝对 FileRef 保持原文件。
- 扫描合并查询，只提交仍匹配的结果；取消在文件遍历之间检查，不能强行中断系统内已经阻塞的读取。
- 平台剪贴板 Adapter 只处理单次读取资源，macOS 临时文件不跨操作共享。

`App` 路由交互并同步当前工作目录；`Renderer::prepare` 维护布局、命中区域并解析导航与可见滚动范围，读取草稿生成画面；`Controller` 管理会话操作与运行时。没有拒绝专用命令、恢复队列、恢复结果枚举或新的 Provider trait。

## harness 保留的必要区分

`submit` 成功表示入队，`admission.rs` 决定是否能提交历史：

| 结果 | 输入去向 |
|---|---|
| 历史提交成功 | 移除待处理输入，继续模型执行 |
| 无效附件或 Prompt Hook 明确拒绝 | 发出拒绝事件，记入最终报告，移出待处理队列 |
| 暂时 I/O、存储失败、超时或取消 | 保留未提交输入到 pending，供执行重试 |
| 拒绝通知无法交付 | 保留输入，按断连终止 |

事件用于交互式调用方；`TurnOutput.rejected` 用于不消费事件的非流式调用方。它们是同一结果的两种交付渠道，不是两份 UI 恢复状态。TUI 已在提交时记录历史，无需靠拒绝事件再保存一份。

附件准备在阻塞工作线程运行，取消后的只读工作不能提交历史。相对 FileRef 按会话目录解析。目录条目错误仅使列表不完整，不应拒绝整个目录；目录打开失败单独报告。

## 验证重点

真实按键和宿主事件覆盖：拒绝不覆盖新编辑、↑找回文字与附件、↓返回原草稿、会话切换后仍可找回、历史副本修改不污染原记录、迟到图片不串到历史条目，以及多行光标行为。接纳测试继续验证坏输入不堵队列、暂时历史写失败保留原输入且重试只提交一次。

## 界面与会话状态

`View` 保留草稿、主题、模型选择和唯一的完整模型候选列表；`SessionView` 保存对话、用量、标题和运行状态。切换成功只替换 `view.session`，关闭选择弹层，保留操作期间的编辑。模型列表的展示、导航和选择都使用同一份 `ModelChoice`，不再维护标签副本。

标题由会话恢复逻辑统一读取或补全，只从持久化历史中的普通用户消息生成，跳过运行上下文和压缩摘要。启动恢复、后台刷新与关闭会话使用同一规则；写入成功后才更新界面标题，失败由下一次刷新重试，不再为每次提交启动独立的标题保存任务。
