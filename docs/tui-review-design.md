# TUI 使用体验与实现修订设计

状态：PR #3 的 review 修订规范。本文取代 tui-redesign.md 中与其冲突的布局和交互规则；旧文档保留为历史记录。

## 目标与范围

用户始终能回答：AI 正在做什么、改动是否成功、是否需要我操作、如何继续或停止。
保持 Core 契约 / Harness 运行时 / TUI 展示分层。本轮修复交互边界、信息层级、工具结果可观察性和历史渲染成本，不重新设计 agent loop。

竞品调研与后续优先级见 [现代终端与 Coding Agent 产品调研](terminal-product-research.md)（2026-09-24）。其中候选功能不代表已经实现。

## 产品定位与视觉系统

YourAI 是以开发任务为中心的现代工作台。终端是当前呈现载体，产品仍需具备成熟应用的层级、反馈、可发现性、连续性与一致性。科技感采用精确排版、克制的冷色焦点和及时状态反馈：纯黑画布 #000000、输入表面 #181818、提问表面 #101010、代码表面 #0B0B0B、暖柔白正文 #E8E6E3、低饱和灰蓝焦点 #A8B8D0。成功/失败/权限继续使用明确的语义色；代码高亮遵循统一色槽，不随意增加装饰色。

初始界面采用简洁品牌字标、任务引导和继续工作入口，移除 ASCII 大字与终端信息面板。开始对话后字标退出，不新增顶部标题。工作中以消息流为主、Todo 为可收起辅区、输入区为全宽操作区域；所有空间变化遵循同一套布局。反馈仅在用户需要时出现：回看时出现返回入口、运行时出现操作状态、失败时呈现诊断。

本轮落实视觉基线、空态与关键交互。完整工作台仍需后续针对真实任务验证，以及建立可追溯的改动/验证结果汇总；当前版本不宣称这些能力已经具备。

## 产品验收：让一次开发任务更容易完成

首要目标不是增加屏幕信息，而是减少找问题、辨认状态、定位错误和继续操作的成本。评价按以下流程进行，不以装饰数量衡量完成度。

| 开发环节 | 用户需要判断 | 交互与验收 |
| --- | --- | --- |
| 提交需求 | Enter 是新任务还是中途补充？ | 空闲提示输入任务；运行中提示 Enter steer 与 /queue 下一轮。草稿保持可编辑。 |
| 等待执行 | 正在做什么，能否停止？ | 输入区上方显示当前动作与 Esc，普通工具输出保持次要层级；不重复添加状态栏。 |
| 查看错误 | 命令为什么失败？ | 折叠 shell 失败预览优先 stderr 尾部五行，明确来源与范围；Ctrl-O 保留完整 stdout/stderr。尾部只是预览，不能冒充自动根因分析。 |
| 阅读结果 | 从哪里开始，哪些是正文与代码？ | 用户问题用色块和字重定位，正文自然分段；代码保留语法与底色，工具过程缩进。无角色标签与滚动条。 |
| 回看历史 | 是否还在跟随最新输出？ | 离开底部时在输入区已有下留白显示返回入口；点击或 Ctrl-End 返回，返回后入口消失。不抢走用户的阅读位置。 |
| 继续任务 | 要补充、排队还是换上下文？ | 延续现有 Enter、/queue、/new、/clear；单行底栏显示 ctx 与权限，窄屏优先保留影响决策的信息。 |

后续验证应使用真实的“修改文件—运行测试—失败修复—阅读总结”任务，关注找到原始问题、发现错误、返回最新输出所需操作和误操作。自动测试只证明交互契约，不替代实际终端试用，也不声称已经测得效率提升。跨工具的变更汇总与结果导航需要可靠的轮次/文件数据后再设计，不能从自然语言猜测完成状态或隐藏失败。

## 信息架构

- 对话与修改结果占据主区域。无 Todo 时不显示常驻侧栏；有 Todo 且宽度至少 80 列时显示 28–40 列任务面板；窄屏显示单行任务摘要。Ctrl-T 收起。
- 忙碌时输入框上方显示当前动作、经过时间及 Esc 停止提示。底栏不再重复动画。
- 底栏始终只占全窗口宽度的一行，Todo 不侵占底栏。正常宽度显示标题、目录、累计 token、ctx、最近回复速度和权限。按 Unicode 显示宽度测量：优先保留 ctx 与权限，放不下时依次省略排队数量、速度、token，并用 … 提示；标题保留开头、路径保留末尾。模型与完整统计在 Ctrl-B 查看，不截断数值或单位。无速度数据用 —，不伪造实时值。
- 颜色与文字共同表达语义：绿色成功、黄色告警、红色失败、黄色/琥珀色强调高权限模式。YOLO 始终显著；宽度不足时先裁次要信息。
- 最小主界面为 30×10；全部覆盖层尺寸都限制在实际终端内。仪表盘支持滚动，短窗口也能访问完整内容。

## 交互契约

使用单一 Overlay 状态表达 Help、Stats、Models、Sessions、Themes；同一时刻只激活一个。
覆盖层优先消费键盘、粘贴和鼠标；Esc 关闭当前层，不能取消背后的任务。Ctrl-Q 始终退出。
选择器统一支持上下方向键与 Ctrl-P/N。空列表明确提示，不允许无效索引。粘贴到会话搜索框只改变查询，不污染消息草稿。
会话删除先显示标题与 ID，必须显式按 Y；Enter 不默认删除，N/Esc 返回列表。当前会话不能删除。
启动器返回明确的 Resume / New / Quit 结果，避免把退出误解释成创建会话。

## 阅读与输入（第二轮产品修订）

用户提问是每一轮的视觉起点：整行底色、加粗正文和上下留白。AI 正文保持自然阅读流，工具卡片维持较低视觉权重。
取消顶部标题、分隔条和问题摘要栏，会话标题仅出现在底栏。Ctrl-Home 回到最新问题，Ctrl-↑/↓ 跳到前后问题，Ctrl-End 返回最新输出。长回复结束不强制改变滚动位置。
轮次索引在 timeline 排版时按稳定条目 ID 生成，不参与工具折叠 hit-test，不因跳转重新解析正文。
输入区移除外框、状态标题和常驻快捷键，只保留柔和底色、› 提示符与空态提示；高度为文本行数加上下两行留白。滚动条完全隐藏，滚轮、PgUp/PgDn、Ctrl-Home/End 与轮次跳转仍有效。Todo 与正文用空白分隔，不画贯穿输入区的竖框。
输出按用户提问（底色、加粗、留白）、Agent 正文（两列缩进、Markdown 标题），不显示 YOU / AGENT 角色标签、工具过程（较低视觉权重、默认摘要）、思考（折叠）分层。底栏始终一行。
深色采用纯黑主背景、浅色采用暖白底，低饱和灰蓝只强调交互焦点，告警保留琥珀色。用户提问和输入框使用抬高明度的表面，Todo 背景与正文一致，避免大面积装饰色。保持正文与次要文字的清晰对比；沿用语义色槽机制，所有主题保持一致的结构。

## 会话与权限命令

- `/new` 开启新会话；`/clear` 是明确的“重置上下文”别名，同样创建新会话。旧记录保留在 `/sessions`，不是只清屏，也不删除历史。保留模型/variant、主题、工作目录配置及本次进程的权限选择。
- 当前轮次、审批、压缩或排队输入未结束时不切换会话；先 Esc 停止，等待结束。准备失败保留原会话。
- `/yolo` 或 Ctrl-G 切换；`/yolo on|off` 显式设置。Harness 在运行时空闲门控内更新 security provider；关闭时恢复原 policy，包含 trusted-shell 设置及已有规则。CLI 启动的 YOLO 同样可关闭。
- 切换影响后续轮次及其新子代理；已在执行中的工具/子代理不追溯修改，也不自动回答已有审批或普通提问。运行中请求切换会提示先停止。权限选择不写入持久规则文件。

## 工具卡片

卡片摘要服务于判断结果：文件路径、diff、退出状态、失败原因优先。
已知工具保留类型化显示；未知工具保留有界、完整结构化输出，折叠时可摘要，展开后必须能查看字段值。
控制字符清理和显示长度限制继续生效；截断明确标注。

## 模型与费用

模型选择失败保持原模型、上下文和配置。模型相关超时与上下文在同一空闲门控内更新。请求 gate 按 provider 和请求策略复用，切回时保留冷却和节流；不同 provider 独立 gate，共享总调用/token 预算及累计指标。已启动的 Hook/子代理仍使用原模型及原 gate。
未保存逐请求价格快照前，不把会话累计 token 乘当前模型价格展示为会话费用。仅展示当前模型单价，避免切模型后重算历史成本。

## 实现边界与性能

- overlay 模块负责覆盖层状态与输入路由；ui 主循环负责执行路由产生的动作。
- renderer 负责屏幕布局；独立 timeline/cards 模块负责单个条目的排版与工具预览。
- 历史条目以稳定 ID 和内容版本缓存。追加 token 只使变化的条目失效，主题/宽度变化才全量重排。
- spinner/时间更新只更新运行中工具标题，不重新解析历史 Markdown 或高亮代码。折叠、选中与恢复历史必须正确失效；淘汰历史时释放缓存。
- 性能验收看“不变历史重新解析次数”，不用机器相关毫秒阈值作为测试门槛。

## 交互更新与终端提交契约（2026-09-26）

原 `FrameSnap` 手工镜像显示字段，菜单选择/关闭、完整拖选范围、窗口尺寸和 Renderer 内的导航意图都曾漏登记。局部绘制测试不能发现没有调用绘制的问题，因此不再以模型字段快照判断是否输出。

当前流程：输入/运行时事件 → 更新状态 → `Renderer::prepare` 完成布局、解析导航并生成 `Canvas` → `Presentation` 比较完整 cell buffer 与光标 → 仅在结果改变时提交终端。终端提交只复制准备好的画面，不再负责消费导航意图。添加显示字段无需修改另一份失效字段列表。

职责与约束：

- `ui/presentation.rs` 管完整画面、光标、12ms 最小提交间隔及合并后的待提交请求。帧间隔到期单独唤醒主循环，输入与输出不等待周期时钟。100ms 时钟用于动画、统计和超时；未改变的画面不写终端、不重置光标闪烁。
- `ui/navigation.rs` 同时拥有阅读偏移与待执行意图。返回底部、手动滚动会原子取消旧意图；同批多个意图以最后一个为准。调用者不再配对调用 Renderer 清理与 View 跟随。
- 布局重排前按稳定条目 ID 与条目内行偏移记录阅读位置，重排后重新定位，覆盖尾部增长、头部淘汰和窗口尺寸改变。被淘汰的条目回退到最早存活条目，被折叠的条目回退到分组标题；宽度变化保留条目内行偏移，不承诺字符级锚定。
- `terminal.rs` 的 DECSTBM/SU/SD 优化只接受全宽区域，局部宽度视口使用普通差分。无论旁边是 Todo 还是未来其他内容，都必须与完整绘制得到同一个屏幕。
- 时间线排版缓存继续由条目 ID/版本控制；准备画面不会重新解析不变的历史。代价是周期性准备和比较可见画面，以屏幕大小为界，不再维护易遗漏的模型镜像。动画按经过时间推进，不随按键或准备次数加速。

回归以三个接口为测试面：Navigation 操作顺序；Presentation 的画面/样式/光标/尺寸和节流；终端输出解码后的整屏等价。`smoke_frames.py` 通过真实 PTY 输入验证菜单、导航、拖选、空闲缩放和无变化时不输出帧；与 `smoke_ui.py` 一起作为 CI 必跑脚本，缺失脚本不再静默跳过。

## 交互编排与会话生命周期（2026-09-26 第二轮）

第一轮契约解决“是否提交画面”；本轮收敛交互更新顺序与异步副作用的所有权，依据是同日可维护性评审的四项结论。

- **导航组合语义**：相对命令（前后问题）基于尚未显示的待执行目标继续计算，绝对跳转与跟随仍整体替换意图；同批两次“上一问”不再合并为一次。见 `ui/navigation.rs` 的 `jump`，回归覆盖相对导航累积与“最后意图胜出（含跟随/手动滚动）”。
- **输入菜单派生**：`View::menu()` 在访问时从当前草稿与焦点重新派生条目，`sync_menu` 调用点全部删除。调用者不可能读到过期菜单，也不再需要记住同步时机。
- **会话生命周期**：`ui/session.rs` 的 `Controller` 拥有运行任务、事件通道、压缩与统计任务（`ui/session/{runtime,setup}.rs`）。列表、删除、切模型、开新会话与恢复均为后台操作：进行中操作序列化互斥（提示保留草稿，不阻塞编辑、导航与绘制），完成后经 `poll` 应用效果。切换成功换用带独立通道的新 Runtime，旧任务的迟到结果无法进入新界面；在途草稿编辑与主题选择保留。迟到的会话列表不会重新打开已被 Esc 关闭的选择器；排队输入与压缩守卫同时覆盖新建与恢复；退出时等待而非丢弃在途效果，成功准备的候选会话也会被正确关闭。
- **时间注入**：`ui/frame_time.rs` 在 UI 边缘对每个准备帧采样一次（单调时钟 + Unix 秒）传入 `Renderer::prepare`；渲染辅助不再自行查询时钟，动画与过期逻辑可确定性重放。

主循环 `ui.rs` 只保留输入路由、动作调用与画面提交；会话任务的取消与收尾统一进入 `Controller::close`。`Renderer::prepare` 维护布局缓存与命中区域、解析导航意图的职责不变；仅当准备阶段顺序再次造成问题时才拆出独立布局解析阶段。

本轮验证：TUI 118 项测试通过（1 项忽略），新增会话控制器三条回归（存储等待不阻塞 UI、失败切换保留原会话且成功切换保留在途草稿、排队守卫覆盖新建与恢复）；工作区测试、`fmt`、Clippy `-D warnings` 及五个离线 smoke（`smoke.py`、`smoke_launcher.py`、`smoke_models.py`、`smoke_ui.py`、`smoke_frames.py`）全部通过。

## 动作层（2026-09-26 第三轮）

第二轮评审指出 `ui.rs run()` 仍是浅模块：481 行、九参数、约七项职责，命令副作用因“需要循环局部变量”内联 98 行，是全模块唯一零测试的接口。本轮把它收敛为动作层，采纳的形状经三个独立设计对比后确定：**不引入翻译层或 Action 枚举**——路由快照（Routing）会重演 FrameSnap 的手工镜像问题，而每个 Action 变体的执行照样需要全部局部量，枚举只是给现有代码行改名（负杠杆）。

- **`ui/app.rs`**：`App` 结构体收纳六个循环局部量（controller/view/meta/renderer/choices/clipboard_task），单入口 `handle(Event) → Flow` 同步解释一个终端事件并应用全部状态变化。异步工作只在此 spawn，由 `poll` 与帧尾和解；`Flow::Quit` 是循环唯一无法本地表达的控制流（丢弃批内剩余事件、跳过帧尾）。私有分解 `key`/`binding`/`submit`/`overlay_action`/`mouse`/`paste` 保持路由顺序可读，菜单 Tab/Enter 的落穿保持结构性向下流而非布尔返回值。
- **键路由顺序即行为契约**（`App::key`）：Release 过滤 → Ctrl-Q → Alt-C/Ctrl-Shift-C 复制 → Esc 清选区 → 无条件清选区 → overlay（`Some` 即消费）→ 命令菜单 → 键位表 → 编辑器兜底。
- **`Editor::key`**：readline 键映射从 `ui.rs` 的自由函数 `edit()` 迁入 `editor.rs`，与 `Overlay::key` 形成同一惯例——输入解释住在被解释的类型上。
- **`ui.rs` 收缩为循环骨架**（691 → 178 行）：唤醒策略（select! 四路 + 2ms/512 合帧）、每事件一次 `handle`、帧尾四件套（`sync_todos`/`settle_clipboard`/`pressure`/`paint`）与清理。帧尾方法不触碰终端；`App::poll` 吸收会话切换后的 meta 刷新与 renderer 重建。
- **测试**：`session::fixture`（离线 mock provider）提升为共享助手；新增 11 项动作层回归锁定此前只有 PTY 能碰的行为——Esc 优先级级联（清选区不中断、二次 Esc 才中断）、Alt-C 空选区吞键、Ctrl-Q 压过 overlay、菜单 Enter 同事件补全并分发 vs Tab/参数命令只补全、未知命令与 /yolo usage 的通知语义、提交管线（user 条目 + Ctrl-P 历史）、/new 切换保留在途草稿、粘贴三级路由与 overlay 期鼠标吞噬。`render.rs` 测试对 `click_dispatch`/`wheel_dispatch` 的越界引用改走 `app` 模块。
- ~~观察到的既有行为：`/yolo` 分发在解析参数前清空草稿，usage 错误不恢复草稿；ask 回复经 `host.submit` 直达，绕过控制器的会话操作互斥守卫。~~（两项均已修复，见第五轮。）

本轮验证：TUI 129 项测试通过（1 项忽略），工作区 329 项通过；`fmt`、Clippy `-D warnings`、五个离线 smoke 全部通过——PTY 端到端行为与重构前一致。

## 状态所有权与接缝数据流（2026-09-26 第四轮）

第三轮评审剩余四项长尾，本轮完成其中三项；Renderer 布局解析阶段的完整拆分维持既定延期。

- **原生滚动窗口改为显式数据流**：`Renderer` 不再持有终端后端的共享单元（删除 `with_scroll_region`），`Canvas` 携带本帧的滚动窗口，`Presentation::flush` 在 draw 之前发布它。原先“compose 期间写终端状态、仅因 prepare 在 flush 内先于 draw 才正确”的隐式顺序耦合，变成 flush 内可见的三步（autoresize → 发布 → 比较/draw）。`Canvas` 的相等性只比较画面与光标；窗口是后端配置，不是像素。无窗口的帧（过小终端）不触碰既有值，与原行为一致。
- **yolo 镜像收敛到所有者**：`Controller` 持有当前会话的权限模式（`set_yolo` 成功后更新，`switch` 内部读取并传给新会话，不再作为参数穿线）；`Metadata.yolo` 由 `App::paint` 每帧从 Controller 刷新，成为派生值而非手工镜像。Ctrl-G 与 `/yolo` 的 Toggle 均读 Controller。
- **Todos 成组封装**：`todos/todo_panel/todo_scroll` 三字段合并为 `state::Todos`——`set()`（滚动位置按设计在列表缩短后存活，有测试钉住）、`nudge()`（饱和）、`scroll_within(max)`（显示期纯读取钳制）、`panel_open()`。六处散改与渲染期隐式钳制集中到一个模块。
- **usage 计量语义命名**：`usage/recorded_responses` 转私有，三种写入语义成为仅有入口——`restore_usage`（恢复，覆盖）、`replace_usage`（压缩完成，替换计量但保留计数）、`accumulate_usage`（流式增量）与 `set_response_count`（存储轮询，计数权威）。模型对 `model_label+pricing` 合并为 `state::ModelInfo`，与 `setup::ModelSelection` 统一为同一类型，配对修改不再可能拆散。
- **Todo 同步改为变更驱动**：`TaskBoard` 增加提交版本号（create/complete 提交后递增），`App::sync_todos` 仅在版本变化时复制排序整个任务表；会话切换时重置已同步版本。原先每次唤醒（输入、tick、流式输出、帧到期）都锁+克隆+排序整个任务表。

## 会话切换后的输入死窗口（2026-09-26 第六轮）

外部评审发现 `smoke_ui.py` 在本工作区 3/3 稳定失败（HEAD 通过）：`/clear` 后立即提交 "after reset"，模型请求从未发出。根因是第五轮会话生命周期引入的互斥过宽——切换成功（`Effect::Opened` 应用、新视图上屏）后，旧会话的收尾（`Effect::Retired`）仍占用 `operation` 守卫；在旧会话 close 的存储 I/O 完成前，`submit`/`reply` 一律被拒（"A session operation is in progress… your draft is kept"）。用户视角：`/new`、`/clear` 后存在一个画面已是新会话、Enter 却被丢弃的死窗口，必须再按一次。

- **收尾从互斥锁中拆出**：`Controller` 新增 `retired` 字段单独持有旧会话的 close 任务（`Effect::Retired` 变体删除）。`available()`（会话变更：list/delete/model/switch/compact/set_yolo）继续同时检查 `operation` 与 `retired`——切换不得与被替换会话的收尾竞态；`accepting()`（用户输入：submit/reply）只检查 `operation`。收尾窗口内的 Enter 直接落入新会话：`submit` 成功后本就调用 `runtime.resume()`，新 driver 立即开跑；旧会话并发写由存储层串行化（每 harness 独立 SQLite 连接，WAL + 5s busy timeout），且切换期间新旧 harness 并发读写本已存在（open_session 的 restore 读 vs 旧会话存活写）。
- **收尾完成的通知与 resume 语义不变**：`poll` 先结算 `retired`（丢弃排队输入的警告、关闭失败错误、resume 新 runtime、"Session ready" 通知），再结算 `operation`；`close()` 改为分别 await 两个句柄——候选会话仍被正确关闭，旧会话收尾等待完成以保证数据落盘，结果在退出路径只丢弃通知。
- **回归**：新增 session 层测试用 oneshot 钉住 retire 窗口，断言窗口内 `submit` 放行、`list` 仍被互斥、收尾完成后丢弃通知如常出现；既有 `ask_reply_shares_the_mutation_guard`（用户操作阻塞输入）与 `failed_switch…`（`finish` 助手补等 `retired`，`old.host.status() == Closed` 断言不再竞态）继续通过。

本轮验证：TUI 135 项测试通过（1 项忽略），工作区 335 项通过；`fmt`、Clippy `-D warnings`、五个离线 smoke 全部通过（`smoke_ui.py` 修复后连跑三次均过）。

### 当前颜色方案：内容优先的中性深色

低饱和灰蓝 #A8B8D0 用于当前操作、运行状态和导航焦点；选中底色 #292828 接近中性。成功、失败、权限保留语义色，代码使用柔和的语法色。重点是阅读路径清楚，而非增加高亮数量。
