# Server 实施计划

状态：尚未实现网络 Server。当前 SessionController 是进程内后端；TUI 已通过它发送操作、接收事件与快照。后续 Server 复用这套控制逻辑，不在 UI 或协议层复制执行流程。

## 职责边界

- SessionManager：拥有会话配置、持久化状态和存储租约；每轮读取并冻结 ExecutionOptions。
- SessionController：唯一调度输入、执行、取消、压缩及会话操作；后端负责准入检查。
- Server：拥有运行中的控制器、客户端连接和事件订阅；协议处理只解析请求、调用后端、编码结果。
- TUI 与其他 UI：显示状态、收集操作；客户端断开不取消后端执行。

不增加全局万能 Config，不提前设计多协议 Transport trait，也不为每个请求新增行为对象。启动设置继续属于 SessionOptions，运行配置继续属于 SessionManager。

## 实施顺序

1. **分离连接与会话生命周期（命令句柄与独立订阅已完成）。** SessionController 拥有 worker，SessionClient 提供可克隆命令与快照；释放客户端不停止执行，所有者 close/Drop 才关闭。关闭不等待客户端释放发送端。SessionClient.subscribe() 提供独立订阅，释放订阅只影响该消费者；缓冲保留 1024 条，落后明确报告 Lagged。未来服务持续持有所有者，服务退出等待关闭与存储释放。
2. **明确会话寻址。** 服务按 SessionId 管理唯一运行实例。当前控制器的 switch 是单客户端选会话流程；服务中客户端选会话不应替换其他客户端正在使用的实例。复用打开/恢复实现，避免重写存储与执行流程。
3. **实现一种通信方式。** 首版使用 HTTP 请求与 SSE 事件流；接口覆盖提交、回复、取消、压缩、配置/模型更新、查询、显式关闭。响应区分已接受、忙碌、无效请求与执行失败；已接受不等于已完成。先监听本机，开放远程前落实身份与会话访问检查。
4. **实现事件恢复和背压。** 事件带会话 ID 和递增游标；定义有限保留窗口。游标过期时明确要求读取快照，不能静默漏事件。慢订阅者不能阻塞执行，也不能无限增长内存；快照说明对应的事件位置。
5. **保证重试与多客户端一致性。** 请求 ID 去重，审批重复回复只产生一次效果；并发配置更新明确版本检查。保持现有存储 fencing，不能让网络层绕过它。
6. **接入 TUI 并清理旧路径。** TUI 使用同样命令与事件语义；删掉迁移后的进程内装配路径。再接第二种 UI 验证后端没有终端依赖。

## 验收

- 两个客户端连接同一会话，只运行一个执行实例。
- 客户端断线后任务继续；重连能恢复快照及可保留事件。
- 取消、显式关闭、服务退出分别测试；关闭后释放存储所有权。
- 重试提交与审批不会重复生效；并发操作有确定的接受/拒绝结果。
- 慢客户端、事件窗口过期、服务重启恢复、过期租约写入拒绝均有集成测试。

## 本轮前置重构

控制器操作准入集中到一个入口，删除由调用者传入的 idle 布尔参数；删除/切换的会话身份检查与操作登记使用同一把锁。steer 的忙碌检查、排队计数与发送也在同一临界区内，避免检查后切换会话的竞态。后端错误不再声称 UI 草稿已保留：草稿属于 UI，后端只能报告操作状态。

本轮未新增或删除 struct/trait；类型清单仍为 227 个 struct、16 个 trait、74 个 enum。这里记录 Server 的目标与待办，不代表 Server 已完成。


## 生命周期前置重构已完成

新增 SessionClient 作为无执行所有权的命令/快照句柄，移动现有字段和方法而非添加一套控制实现。当前统计为 228 struct、16 trait、74 enum。独立订阅已实现，网络尚未实现；Server 内的会话注册表和逐会话寻址仍待实施。


## 独立订阅前置重构已完成

SessionSubscription 表达一个消费者的读取位置，SessionEvent::Lagged 明确报告覆盖的事件数。新订阅不回放旧事件，尚无持久化恢复游标或原子快照/事件位置。当前统计更新为 229 struct、16 trait、74 enum；后续先整理按会话寻址，再落实网络恢复协议。
