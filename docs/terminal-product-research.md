# 现代终端与 Coding Agent 产品调研

调研日期：2026-09-24。目标：为 YourAI 的产品结构、视觉系统与交互设计提供依据。

证据范围：官方文档、官方主题源码、官方公开截图；未进行这些产品的完整安装试用。截图代表所展示版本和主题，不等同于所有用户的当前默认外观。下文将观察与设计建议分开，建议尚未全部实现。

## 1. Warp：学习完整应用的结构

### 配色与视觉事实

官方仓库中的 `Warp Dark` 定义为纯黑背景 `#000000`、前景 `#FFFFFF`、强调色 `#00C2FF`。这是一个具体内置主题，不代表 Warp 所有界面的唯一配色。[固定版本主题源码](https://github.com/warpdotdev/themes/blob/0c25023808ef683493c9404260844cb060a79c2f/warp_bundled/warp_dark.yaml)

官方主题预览使用黑底与青蓝焦点；当前产品页面中的 Agent 示例则使用深灰画布、稍亮的操作块、白色正文与低权重的过程文字，并展示任务及代码审查区域。这些截图表明其界面会随主题和工作状态变化。[主题预览](https://docs.warp.dev/terminal/appearance/themes)、[产品截图](https://www.warp.dev/terminal)

Warp 的主题设计将 ANSI 文字颜色与 UI accent 分开，主题延伸到标签选中、块选中等交互区域。这是整套界面的一致性设计。[主题设计说明（2021 年，作为设计原理参考）](https://www.warp.dev/blog/how-we-designed-themes-for-the-terminal-a-peek-into-our-process)

### 交互事实与借鉴

Warp 将输入和输出组织为 Blocks，可按块导航和操作；输入位置支持底部固定等模式。长输出的 Sticky Command Header 可定位所属命令，点击回到块开头。[块模型](https://www.warp.dev/blog/block-model-behind-warps-agentic-development-environment)、[输入位置](https://docs.warp.dev/terminal/appearance/input-position)、[长输出导航](https://docs.warp.dev/terminal/blocks/sticky-command-header/)

**对 YourAI 的建议：**以一次用户请求为阅读单元，问题、过程、结果共享稳定的定位关系。保留已实现的轮次跳转，并让入口可发现。用户明确不需要顶部标题，不能直接照搬吸顶标题；优先使用输入区现有留白中的按需导航。普通输出块应可复制、展开并定位到相关文件，操作只在选择后出现。

## 2. OpenCode：学习灰阶表面与信息密度

官方默认 `opencode` 主题的深色定义如下。网站截图可能使用不同版本或模式，不能用截图里的蓝色反推默认主色。[固定版本主题源码](https://github.com/anomalyco/opencode/blob/fe0c4f8c74385ab4c4bb14dfe594a5f5ac91e65a/packages/tui/src/theme/assets/opencode.json)

| 用途 | 色值 |
| --- | --- |
| 主背景 | `#0A0A0A` |
| 面板背景 | `#141414` |
| 元素背景 | `#1E1E1E` |
| 正文 | `#EEEEEE` |
| 次要文字 | `#808080` |
| 主色 | `#FAB283` |
| 次色 | `#5C9CF5` |
| 强调色 | `#9D7CD8` |

官方公开的会话截图以宽文本流为主，用户问题和输入区有低对比底色，工具调用相对正文降低权重。[官方仓库截图](https://github.com/anomalyco/opencode/blob/dev/packages/web/src/assets/lander/screenshot.png)

交互提供文件引用、工具详情切换、外部编辑器和会话等命令；主题也定义 Markdown、diff、语法等独立语义色。[TUI 文档](https://opencode.ai/docs/tui/)、[主题机制](https://opencode.ai/docs/themes/)

**对 YourAI 的建议：**学习多级表面和明确语义色。现有统一 PANEL 同时服务问题、输入、代码，未来应允许各自调节层次，而不通过加框区分。保持用户要求的纯黑背景和清晰次要文字，不直接照搬较暗的 `#808080`。不引入截图中用户已明确取消的顶部标题和多行底部信息。

## 3. Claude Code：学习按需展开与编辑连续性

官方交互文档提供详细 transcript 视图、默认折叠的工具信息、用户问题之间的跳转、历史搜索、草稿暂存以及多行编辑。主题和代码高亮可配置；本次未核实其当前默认主题的完整色值，故不凭品牌色推断 CLI 配色。[交互文档](https://code.claude.com/docs/en/interactive-mode)

**对 YourAI 的建议：**默认阅读路径优先展示回答和关键结果，工具过程按需展开；保留完整输出与错误。菜单、会话检索、日志查看的打开和关闭都应保留草稿、光标与阅读位置。命令及快捷键在相关操作附近出现，减少背键位的成本。

## 4. Codex CLI：学习开发任务的闭环

官方界面示例采用文本主导的任务流，提供模型、权限、review 等入口；文档强调在同一会话中查看命令、diff 并继续指示任务。本次不推断固定配色。[官方 CLI 页面](https://developers.openai.com/codex/cli/features)

**对 YourAI 的建议：**完成态应回答“改了什么、执行了哪些验证、还有什么待处理”。汇总需来自可追溯的事件和文件信息；不能把某条命令退出码为 0 等同于所有测试通过，也不能把计划状态当作代码实际状态。

## 5. Ghostty：学习应用品质

Ghostty 将速度、功能和符合系统习惯的原生体验作为并列目标，并明确区分启动、滚动、吞吐和帧率等不同速度指标。[官方介绍](https://ghostty.org/docs/about)

**对 YourAI 的建议：**把长输出期间可持续输入、滚动不跳、中文选中正确、复制不夹带装饰、调整窗口保持位置列为发布条件。视觉效果和响应品质共同构成现代应用体验，不能只用空闲截图判断。

## 6. 对现有设计的修正

当前设计保留研究中的灰阶分层与一致的交互反馈，但撤下此前直接引用的 Warp 青蓝：用户反馈该方案不协调。默认主题改为纯黑、暖柔白、中性灰表面；标题与结果区靠字重组织，低饱和灰蓝仅用于交互焦点。具体色值与约束见 `tui-review-design.md` 的“当前颜色方案”。

已实现：无角色标签、无应用滚动条、单行底栏、默认五行输入、Markdown 分层、代码底色、轮次快捷跳转、历史返回入口、失败 stderr 优先预览。

尚需设计与实现：按轮次汇总的过程组、文件变更/验证结果的汇总、内容块级操作、对话检索。以下为产品建议，不是已上线功能。

| 优先级 | 改进 | 验收情景 |
| --- | --- | --- |
| P0 | 问题定位入口可发现 | 阅读长回复中段时，无需寻找历史记录即可回到所属问题；不加常驻顶栏 |
| P0 | 连续普通工具过程可收起为一组 | 连续多次 read/search 不淹没回答；失败、待审批及关键 diff 保持可见；完整过程可恢复 |
| P0 | 有依据的结果摘要 | 一轮结束后能找到变更文件、已运行验证及失败；缺少证据明确显示未知 |
| P1 | 选中内容后的局部操作 | 复制回答/代码、展开工具、打开文件的作用范围明确；复制不带角色标签或状态栏 |
| P1 | 全流程输入连续性 | 检索、选择模型、阅读日志后返回，草稿、光标及阅读位置保留 |
| P1 | 语义表面细化 | 问题、输入、代码可辨认；强调色集中于当前焦点，常规正文保持安静 |

以“提出修改—多次搜索—编辑多个文件—测试失败—修复—阅读结果”为统一样本，对比完成操作数、定位失败所需时间、回到问题所需动作和滚动位置稳定性。本次调研不宣称已测得效率或眼疲劳改善。

## 实施跟踪

2026-09-24 后续实现了按请求段组织的 Recorded actions、失败优先、文件/命令分组、点击原始详情及 `/results` 导航。此处是工具证据的操作记录汇总；尚不等同于工作区净 diff 或语义化的测试报告，后两者仍需独立数据支持。
